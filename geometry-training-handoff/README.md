# 几何生成准确性训练 · 交接包

**目标**:让 AI 看一张工程图纸,自动产出**几何正确**的 3D 模型。
**本包自含全部素材与代码**,路径均为包内相对路径。文件完整性见 `MANIFEST.md`(含 md5)。

> 建议先读第 5 节「已知的坑」再动手——前一阶段浪费的时间九成花在坑上,不在模型能力上。

---

## 1. 要解决什么问题

上一阶段实测:规整件尚可,**曲面/回转/环类件几何长期不合格,重建体积偏离真值 2–5 倍**。

更根本的问题是**当时的评分没有真值**——拿「AI 重建件」比「AI 生成的基准件」,自己和自己比。已实测:某零件"预测件"与"基准件"体积完全相同,内部评分满分,而两者相对真实标准件偏差 +12%~+157%。

**所以第一原则:先有真值,再谈分数。**

### 2.2 练习素材(`practice_set/`)

| 文件 | 内容 |
|---|---|
| `practice_3d_sw64.zip` | 66 个 SolidWorks 三维件(.SLDPRT)+ 63 张题图(.jpg)。**按编号配对**:`001.SLDPRT ↔ image001.jpg`,共 63 对(已逐一验证) |
| `practice_2d_dwg100.zip` | 102 张二维图(.dwg) |

来源为公开的建模练习教程。**两包的用途不同,互补不重复:**

- **66 件那包 = "期末考"(端到端)**:题图 → 读参数 → 建模 → 与 SLDPRT 转出的真值几何比对。样本量是真值件的 13 倍,可回答本方案最大的未知数——**建模模板能否跨零件复用**(目前 4 个零件配 4 个模板,若真实比例如此,方案在商业上不成立;必须几十个零件跑过才知道)。但它只给总分,挂了分不清是"读错"还是"拼错"。
- **102 张那包 = "单元测验"(只考读图)**:DWG 是 CAD 矢量文件,**每个尺寸标注可用程序零误差抽取,天然是标准答案**——让视觉模型念图上尺寸,与答案比召回/精确率,单独给"读图"这一步打分。此路线已走通(前一阶段的 `vision-eval-cad100` 评测集即由这 102 张构建,曾用于视觉模型选型)。局限:它验证不了"尺寸安没安对特征",那要靠 66 件的端到端暴露。

**⚠️ 用前必做:.SLDPRT 是 SolidWorks 私有格式,常规几何库读不了**,需先(如用 SolidWorks)批量另存为 STEP。已实测 build123d 读它**不报错但返回体积 0 的空对象**——转换后务必抽查体积 > 0。102 张 .dwg 无需此步骤(dwg→dxf 提取尺寸的路线已走通)。

局限如实说明:练习件无配套工艺规程,只服务"几何"这一半;且未必覆盖 1mm 薄壁筒、深镗腔这类难特征——**用它验证方法与模板复用性,最终仍需回到 5 个真值件确认**。

## 3. 方案与已验证的结论

### 3.1 架构:把"读"和"建"拆开

```
①看图转录(视觉模型) → ②参数归位(推理模型,不看图) → ③建几何(确定性代码) → ④自检重试
```

**依据(实测)**:AI 不是读不出尺寸,而是**把读对的尺寸拼成错误实体**——外筒的 ⌀63.2/⌀52/⌀50/⌀46.2 全读对了,却把 1mm 薄壁空心筒做成了实心棒(体积 +845%);端盖漏挖凹槽。**所以让模型只管认字,"掏空/挖槽"交给写死的程序——程序不会漏。**

②刻意不给推理模型看图,是逼它基于转录推理,而不是重新猜图。实测这一拆分有直接价值:视觉模型没认出"槽"这个特征,推理模型从"两条尺寸都出自 B-B 剖视图"推断出槽宽/槽深。

### 3.2 形状族参数化模板(`code/builders/`)

| 文件 | 形状族 |
|---|---|
| `hollow_tube.py` | 空心回转筒(筒/套/环/管) |
| `tapered_rod.py` | 锥形回转体 |
| `locating_pin.py` | 阶梯销轴 |
| `end_cover.py` | 板 / 盖 |

每个模板 = `build_xxx(spec)` 纯函数 + 参数字典。**结构上保证"先造外形、再必定减内腔",做不出实心件。**

**已验证(独立复核,并检查过建模代码未读真值文件):给对参数,四个模板均精确复现真值** —— 外筒 +0.01%、锥杆 +0.0000085%、定位销 −0.04%、端盖 ≈0。**即:参数对,几何就对;全部难度都在"参数能否从图纸读出来"。**

### 3.3 端到端成绩:1/4(且该分数偏低,见 5.3)

| 件 | 结果 | 卡在哪 |
|---|---|---|
| **端盖** | ✅ 体积/表面积/包围盒三项 0.0%,独立复现两次 | 完整日志见 `evidence/` |
| 外筒 | ❌ | 局部详图里的孔位/倒角尺寸,多轮反馈都没能落位 |
| 定位销 | ❌ | 轮廓断点缺失/不闭合,建不出实体 |
| 锥杆 | ❌ | 最终建成但体积 −21.7%,两个直径方向小 25% |

**已看出的规律**:参数都在主视图、能直接对号入座 → 稳定成功;**需要把局部放大详图的尺寸映射回主体坐标 → 目前的模型跨不过去**。

## 4. 不可动摇的设计约束(防自欺,别拆)

1. **真值绝不进入循环。** 重试反馈只能来自自洽性检查(建出的几何 vs 模型自己转录的尺寸),不能来自"和真值比"——真实产品在推理时没有标准件,拿真值指导重试等于拿答案教学生。真值只用于事后记分。
2. **验收同时卡三项:体积 + 表面积 + 包围盒。** 只看体积会被骗:实测有过体积仅偏 −6.26% 但轴向长度只有真值 2/3 的案例——两个大错互相抵消。参考阈值:|体积|<2%、|表面积|<5%、包围盒各轴<2%。
3. **技术故障 ≠ 能力不足。** 超时/额度/网络导致的失败必须单独标记、不产生分数,否则统计全脏。
4. **失败结果一旦产生就锁定,不许反复重试洗白。** 可以续跑的只有"技术故障中断、没拿到结论"的。

## 5. 已知的坑(最重要的一节)

### 5.1 校验/解析坑 —— 每个都制造过"假失败"

| 坑 | 教训 |
|---|---|
| 坐标 0 被判"缺失" | 位置类字段填 0 是合法的(端面起算就是 0);只有尺寸类字段为 0 才可疑。曾把模型逼进死角连续 5 轮假失败 |
| 转录行号被当尺寸 | 转录常是编号列表,`12. 10` 里的 12 是行号。剥行号的正则须要求分隔符后有空格,否则 `13.5` 会被拆成 `5` |
| 直径标注被正则吞掉 | `φ` 在 Unicode 里算字母,用 `\w` 断言会把 `φ63.2` 整个滤掉 |
| 模板允许为空的特征被判缺失 | 某件本就没有径向孔,模型 4 轮答对、校验 4 轮判错,整件作废。模板示例里本就为空的字段=允许不存在 |
| 物理校验从未生效 | "内孔<外径"实现时误把总长算进外轮廓,恒成立、从未触发。**判定逻辑必须有测试**——`code/test_u4_validate.py` 33 项,第一次运行就抓出此条 |

**纪律:改任何校验/解析逻辑,先跑测试,再烧模型调用。**

### 5.2 提示词坑:硬性规则诱导模型"硬凑"

- 要求"各段之和必须等于总长" → 模型把 19mm 的段压成 2mm 去凑,而不是怀疑总长读错了。
- 要求"转录里的尺寸必须全部用上" → 模型把数字乱塞进分段边界,凑出非法几何。

**这些是好的诊断信号,只能作提示,不能作硬要求。**

### 5.3 接口坑:枚举取值被盲测机制误屏蔽(**未修复,建议第一个做**)

为防泄露尺寸,参数骨架把所有值抹成占位符,**连字段的合法取值(如 `type` 只能是 `cyl`/`cone`)也一并抹掉了**——模型只能瞎猜,反复被拒。**21 个失败轮次约 10 轮死于此,与读图能力无关。这也是 1/4 这个分数测不准(偏低)的主因。**

**用 GPT 有现成解法**:结构化输出(JSON Schema)里直接声明 `"type": {"enum": ["cyl","cone"]}`,`required` 同时消灭"漏字段导致建模崩溃"。**建议接手第一件事就是把参数结构改成带 enum 的 Schema,然后重测——那时的分数才是真实能力。**

### 5.4 调用坑(通用工程教训)

- 推理档模型单次可达数分钟、上万推理 token:**超时给足,长请求用流式**(实测同一请求非流式被网关掐断、流式正常)。
- **故障时绝不静默降级到弱模型**,否则"通道不通"与"模型不行"混在一起,数据全废。
- 健康检查必须走**真实调用链路**,小请求探活会给出假阳性。
- 成本参考:前一阶段 40 次调用消耗 72 万输出 token,**先小批量验证再放量**。

## 7. 怎么确认你的结果是真的

前一阶段在这上面栽过跟头,三条硬规矩:

1. **任何数字现场跑脚本得出**,不要引用文档里的数(包括本文档)。
2. **独立复核**:另找人/另开会话重新加载导出件与真值件、自算偏差;并检查建模代码是否读了真值文件(防"抄答案")。
3. **区分技术故障与能力不足**,故障导致的 0 分会严重污染结论。
